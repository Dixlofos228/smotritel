# Смотритель

Telegram Business бот: архив сообщений, правки, удаления, файлы и инструменты для чатов

Управление в нижнем меню. На главной — архив, удалённые, AI, TikTok, перевод, поиск, погода, голосовые, изменённые, сохранённые, настройки и ещё. Остальные действия лежат в «Ещё». Подсказки ввода удаляются после ответа или отмены

## запуск

Нужны Docker Compose, свободный порт 8787 и примерно 8 ГБ памяти. Модели и архив занимают место отдельно

1. Создать бота через BotFather и включить Business Mode
2. Запустить `python3 scripts/setup.py` — токен вводится скрыто и записывается в `secrets/bot_token`
3. `docker compose up -d --build`
4. Дождаться загрузки Qwen и Whisper: `docker compose ps`
5. Открыть бота, нажать Start и подключить его в настройках Telegram Business

Для команд и автоответов нужно разрешить ответы. Stories, имя и bio требуют своих прав. Бот не получает историю до подключения

Ключи лежат в `secrets/`, настройки — в `.env`. В репозитории есть только `.env.example` и пустая папка ключей

## функции

| команда | что делает |
|---|---|
| `.save` | сохранить сообщение из reply |
| `.q [1–3]` | цитата из текста или фото |
| `.story`, `.story single` | сетка 3×3 или один кадр, предпросмотр и подтверждение публикации |
| `.stat`, `.wrapped [дней]` | статистика и итоги чата |
| `.search @user`, `.watch`, `.watch list`, `.watch stop @user` | полученная история профиля и наблюдение |
| `.weather город` | погода Open-Meteo |
| `.translate ru текст` | локальный перевод |
| `.afk текст`, `.unafk` | автоответ на время отсутствия |
| `.echo`, `.troll`, `.autoreply [on/off]` | режимы ответов для выбранного чата |
| `.mute [30s]`, `.unmute` | пауза ответов бота |
| `.antimute` | зеркало своих исходящих в личку |
| `.ai вопрос`, `.summary` | Qwen и расшифровка Whisper |
| `.tiktok ссылка` или ссылка TikTok | публичные видео/фото через TikWM без знака TikTok |
| `.yandex запрос` | ответ по найденным материалам Bing, источники в чате |
| `.heart` | GIF сердца |
| `.send USDT 0.03` | демочек, денег не переводит |
| `.spam 1–3 текст` | до 3 повторов только в своей личке |
| `.timename`, `.timebio` | часы в имени/bio с восстановлением исходного текста |
| `.screentime`, `.crash` | активность чата и отдельный тест ошибок |

Команды в Business-чате принимает только владелец подключения. Все эти действия также доступны кнопками. Premium и оплата пока демо, произвольные сторонние плагины не исполняются

## данные и сеть

Архив в Docker volume, SQLite/WAL. У каждого аккаунта свои настройки, сообщения и папка файлов. API только на 127.0.0.1:8787, ключ определяется через `/api` в своей личке

AI и речь работают локально. Внешний AI выключен по умолчанию. Погода отправляет город Open-Meteo, поиск отправляет запрос Bing, загрузка TikTok отправляет ссылку TikWM. Перед вводом бот это показывает

Одна тяжёлая задача за раз, до 2 незавершённых задач на аккаунт. Один файл до 20 МБ, по умолчанию 1 ГБ медиа на аккаунт. Сгенерированные файлы удаляются через 7 дней. Текстовый архив автоматически не чистится

«Удалить мои данные» удаляет свой аккаунт и его данные на сервере. Сообщения, уже отправленные в Telegram, и отдельные бэкапы остаются. Администратор сервера имеет доступ к хранилищу

## обслуживание

```bash
docker compose ps
docker compose exec -T bot python scripts/status.py
docker compose restart bot
```

Бэкап делается с остановленным ботом

```bash
docker compose stop bot
docker compose run --rm --no-deps -v "$PWD/backups:/backup" bot python scripts/backup.py /backup
docker compose up -d bot
```

Восстановление: `scripts/restore.py /backup/имя.tar`, только в пустое хранилище. Не делать `down -v` ради обновления — это удаляет volumes

## проверка и git

```bash
python -m pytest -q
ruff check smotritel scripts tests
ruff format --check smotritel scripts tests
docker compose --profile test run --rm --build --no-deps test
```

Включить проверку перед коммитом

```bash
git config core.hooksPath .githooks
python3 scripts/check_repo.py --all
python3 scripts/check_repo.py --history
```

Проверка читает staged-файлы, поэтому подмена файла после `git add` её не обходит. Она блокирует токены, приватные ключи, `.env`, архивы и данные сервера. `.env.example` и `secrets/.gitkeep` разрешены

В готовой копии нет старой истории и рабочих секретов. После создания пустого приватного репозитория GitHub

```bash
git add .
git commit -m "init"
git remote add origin <URL-приватного-репозитория>
git push -u origin main
```

Не копировать `.git` из рабочей установки и не добавлять `.env` или `secrets/` через `-f`
