# как устроено

Python3.12, aiohttp, SQLite/WAL, Docker Compose

`routing.py` определяет аккаунт по Telegram update. На событие создаётся свой Service, общий текущий пользователь не хранится

`tenancy.py` держит контекст аккаунта и перенос старого хранилища. Профиль, настройки, состояние ввода, клавиатура и очереди разделены по владельцу. Сам SQL всё равно должен ограничивать владельца явно

`db.py` хранит сообщения и версии по connection/chat/message. Правка добавляет версию, удаление отмечает запись. Пользовательские файлы лежат в tenants/uid, пути проверяются перед чтением и отправкой

`lower.py` сохраняет подписи кнопок и маршруты. `ui.py` формирует экраны. Telegram получает ReplyKeyboard, без новых inline-кнопок. Отложенный ответ не меняет меню после нового перехода. Delivery читает актуальную панель непосредственно перед отправкой

`jobs.py` выполняет тяжёлые задачи по одной, выбирает давно не обслуженный аккаунт. Polling и архив продолжают работать отдельно

`delivery.py` отправляет outbox и проверяет владельца, поколение, адресата и права. Подсказки/статусы в личке удаляются по собственной квитанции. Текстовый Business-статус редактируется, файловый удаляется отдельным Business API при наличии права

`ai.py` обращается к Qwen/Whisper. `web_search.py` получает Bing RSS и отдаёт материалы локальной модели. `tiktok.py` скачивает play/hdplay или исходные фото TikWM, поле wmplay не используется

`stories.py` готовит кадры и черновик. Публикация требует собственного nonce и прав подключения. `clocks.py` хранит исходное имя/bio и возвращает их после отключения часов

Миграции применяются атомарно при старте. Файлы при переносе сначала копируются и проверяются. После восстановления pending outbox может повторить отправку: Bot API не гарантирует exactly-once
